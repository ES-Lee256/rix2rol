# RIX → ROL 转换器
Converts SOFTSTAR RIX to AdLib ROL and INS, which is the matching instrument file for ROL.

请先从本仓库的 **Releases** 页面下载发行版。发行版包含两个 Windows 程序：

- **`rix2rol_windowed.exe`**：图形界面版本，适合直接选择文件并转换。
- **`rix2rol.exe`**：命令行版本，适合批量处理或在终端中使用。

下载后解压即可使用，不需要另外安装 Python，也不需要下载或运行项目源码。

注：如果下载后遇到`rix2rol_windowed.exe`文件报错或在终端中不能使用`rix2rol.exe`，请使用管理员权限运行`rix2rol_windowed.exe`，或使用管理员权限的命令行或终端运行`rix2rol.exe`。

## 功能简介

本工具将大宇资讯的 `.RIX` 音乐文件转换为 AdLib Visual Composer 可读取的 `.ROL` 工程，并从 RIX 内嵌乐器库中导出对应的 `.INS` 音色文件。

- 还原音符、音色切换、音量和音高事件。
- 输出包含 45 条轨道结构的 ROL 工程及其 INS 音色文件。
- 默认使用适合 Composer 的时间轴设置；遇到过长的曲目时会调整时间网格，保留事件并提示量化误差。
- 转换完成后会对 ROL 结构进行校验。

有关 RIX、ROL、INS 文件结构和转换规则的详细分析，请参阅[格式分析报告](./ROL_RIX_分析报告.md)。

## Windows 图形界面版

双击 `rix2rol_windowed.exe` 启动。

1. 在“输入 RIX”一栏选择要转换的 `.RIX` 文件。
2. 选择输出位置：
   - **选择外部目录**：在输入框填写目录，或点击“浏览”选择目录。
   - **在根目录下保存**：直接保存到 RIX 文件所在目录。
   - **在根目录下的文件夹保存**：在输入框填写文件夹名称；文件夹不存在时会自动创建。
   - 外部目录或子文件夹留空时，自动在 RIX 文件旁创建 `<文件名>_ROL` 文件夹。
3. 如需使用原版默认转换设置，勾选“按照默认参数转换”。勾选后下方参数会停用，转换时忽略其中填写的内容。
4. 点击“开始转换”。完成后可查看运行信息，或点击“打开输出目录”。
5. 如需保存本次控制台输出，在开始转换前勾选“导出日志为 TXT”。日志会保存到输出目录，文件名为 `<文件名>_conversion_log.txt`。

## 命令行版

在终端中运行 `rix2rol.exe`，将输入文件路径作为参数：

```text
rix2rol.exe 曲子.RIX
```

默认会在输入文件旁生成 `<文件名>_ROL` 文件夹。也可以指定输出目录：

```text
rix2rol.exe 曲子.RIX -o 输出目录
```

常用参数：

| 参数 | 默认值 | 说明 |
|---|---:|---|
| `-o`, `--out DIR` | `<文件名>_ROL` | 指定输出目录 |
| `--max-ticks N` | `7500` | 时间轴上限；超出时会尝试使用更粗的时间网格 |
| `--tick-ms MS` | 自动 | 指定每个 tick 的毫秒数 |
| `--bpm BPM` | 自动 | 指定 BPM；需要同时指定 `--tick-beat` |
| `--tick-beat N` | 自动 | 指定每拍的 tick 数；需要同时指定 `--bpm` |
| `--beat-measure N` | `4` | 每小节拍数 |
| `--scale-x N` | `56` | ROL 编辑器横向缩放 |
| `--scale-y N` | `48` | ROL 编辑器纵向缩放 |

例如，指定 BPM 和每拍 tick 数：

```text
rix2rol.exe 曲子.RIX --bpm 120 --tick-beat 4
```

想要更长的精确时间轴，可将上限提高至 ROL tick 字段允许的范围：

```text
rix2rol.exe 曲子.RIX --max-ticks 60000
```

提高上限可能生成超出 AdLib Visual Composer 常见可用范围的工程；如优先考虑 Composer 兼容性，请保留默认的 `7500`。

## 输出文件

转换后会生成：

- `<文件名>.ROL`：音乐工程文件，可在 AdLib Visual Composer 中打开。
- 一个或多个 `.INS` 文件：从 RIX 内嵌乐器记录导出的音色文件。
- 可选的 `<文件名>_conversion_log.txt`：图形界面选择导出日志时生成。

在 Composer 中打开 ROL 时，如提示找不到乐器，可将生成的 INS 文件放在 Composer 能查找的音色目录，或通过 Bank File 加载包含这些音色的音色库。

## 转换说明与限制

- RIX 将音乐事件编码为按毫秒推进的指令流；ROL 则使用 tick 表示事件时间。程序会根据事件时刻选择时间网格。
- 默认上限为 `7500` tick，以兼顾 AdLib Visual Composer 的兼容性。曲目超出上限时会整体调整到更粗的网格，事件保留，但时间精度可能降低；日志会报告量化误差。
- RIX 不保存 ROL 的轨道名称、编辑器缩放等全部工程信息，因此输出 ROL 中这些无法从 RIX 恢复的字段会使用默认值。
- 生成的 `.INS` 来自 RIX 内嵌音色记录；原文件中未被引用的音色等无法通过音乐事件完整恢复的内容不保证保留。

## 支持的游戏

本工具面向使用 RIX 音乐文件的游戏资源，相关游戏包括：

- 仙剑奇侠传(DOS)
- 魔神战记2
- 妖魔道
- 魔法世纪2
- 天使帝国2
- 明星志愿
- 正宗台湾十六张麻将
- 正宗台湾十六张麻将2
- 大富翁3
- 格斗拳王
- 蜥蜴超人L-MAN
- 春秋争霸战2

实际转换取决于输入文件是否为有效且受支持的 RIX 文件。

如果上述对应游戏的`RIX`文件被打包进了游戏资源包内(如仙剑奇侠传(DOS)的`mus.mkf`文件)，则需要将`RIX`文件从对应游戏包中解包出来，并使用本工具进行转换。`rix`专解工具参见我的这个开源项目：[点此跳转](https://github.com/ES-Lee256/Cut-game-package-to-get-RIX)。当然`mkf`文件有专门的打包解包工具，也在Github上有开源项目，详情可以自己查找。
